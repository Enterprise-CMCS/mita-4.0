# Product

This is the **MITA 4.0** (Medicaid Information Technology Architecture 4.0) website — a CMS (Centers for Medicare & Medicaid Services) documentation and guidance site for State Medicaid Agencies.

## Purpose

The site helps state agencies navigate the MITA 4.0 framework, which aligns Medicaid business and IT strategies to achieve enterprise goals, support CMS-prioritized outcomes, and prepare for enhanced funding requirements.

## Key Content Areas

- **Companion Guide** — Step-by-step walkthrough of the MITA 4.0 process (two paths: Targeted SS-A and Full SS-A)
- **Architectures** — Capability, Viewpoints, Business, Information, and Technical reference models
- **Information Architecture** — Data classification framework with crosswalk workbooks
- **IA Data Crosswalks** — Practical mappings of provider, FHIR, health plan, and managed care data to MITA subject areas
- **Maturity Criteria** — State Self-Assessment (SS-A) maturity levels and criteria
- **Outcomes-Based Planning (OBP)** — Framework for defining business challenges, outcomes, and measurable success criteria
- **Implementation Walkthrough** — Plain-language guide through the four-step MITA process
- **Tools & Resources** — OBP tool, SS-A tool, ConOps template, quick reference guides

## Audience

The site serves multiple distinct roles within State Medicaid Agencies and CMS:

| Role | Primary Need |
| --- | --- |
| **Medicaid Director** | Understand the business value and ROI of investing in a MITA SS-A |
| **Medicaid Enterprise Architect** | Model the state enterprise to align Business, Information, and Technical architecture across MITA domains |
| **SMA Leader** | Identify which capabilities to upgrade and plan targeted investment |
| **State Medicaid Person (program staff)** | Understand what it takes to reach a target maturity level (1–5) in a specific capability area |
| **CIO** | Navigate data and information capability maturity criteria and plan a path to a target level |
| **CTO** | Navigate technical capability maturity criteria and plan a path to a target level |
| **CMS Stakeholder** | Review state self-assessment evidence and maturity profiles |

Pages should reflect this role diversity in their hero copy, CTAs, and orientation language where relevant.

## MITA Maturity Levels

All maturity criteria across the site use this standard 5-level scale:

| Level | Label | Description |
| --- | --- | --- |
| 1 | Initial | Ad-hoc, undocumented, no formal approach |
| 2 | Developing | Identified and documented, inconsistently applied |
| 3 | Defined | Standardized and consistently implemented |
| 4 | Managed | Measured, managed, and centrally governed |
| 5 | Optimizing | Continuously improved with enterprise standards |

## MITA Architecture Domains

MITA 4.0 organizes capabilities across three integrated architecture domains. Pages covering maturity criteria should treat these as a unified enterprise model, not independent silos:

- **Business Architecture** — processes, roles, regulations, and business capability areas (e.g., Member Management, Provider Management)
- **Information Architecture** — data governance, quality, exchange, metadata, and information lifecycle
- **Technical Architecture** — applications, integration, infrastructure, security, and data architecture
